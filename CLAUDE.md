# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository structure

This is a monorepo with two independent apps, not yet wired together over HTTP in a finished way:

- `FrontEnd/my-app/` — Next.js 16 (App Router) public site + dashboard, in plain JavaScript (JSX, no TypeScript).
- `BackEnd/my-laravel-app/` — Laravel 13 API (PHP 8.3), Sanctum token auth, currently minimal (one model, two endpoints).

There is no root package manager — each app is developed and run independently from its own directory.

## What this product is

SOS House is a Moroccan marketplace connecting people who need home/trade services (plumbing, electricity, cleaning, etc.) with verified independent artisans. The full functional/technical spec lives outside this repo (cahier des charges); the parts that matter for day-to-day coding:

- **Demand-centric model**: clients publish a request ("demande"), verified providers ("prestataires") respond to it — not a browsable directory.
- **Three provider verification levels** (N0 informal / N1 auto-entrepreneur / N2 registered company) gate which requests a provider is *eligible* to see, independent of their paid commercial tier. This eligibility rule is meant to live in a dedicated backend service, never purely as a frontend check.
- The product is French-first (`lang="fr"`), Morocco-first. Expect UI copy, routes, and content in French.

Treat this context as background for interpreting feature requests, not as a spec to implement wholesale — build what's actually asked.

### Architecture
- **App Router, route groups**: `app/(site)/` holds the public marketing site (header/footer layout, homepage, 404); `app/dashboard/` is a separate authenticated area outside that group. `app/layout.jsx` is the root layout (fonts, global `Toaster`, `TooltipProvider`); `app/(site)/layout.jsx` adds the public `Header`/`Footer` chrome on top of it.
- **Component split**: `components/Main/` = homepage marketing sections (Hero, Services, Testimonials, etc.), composed together in `app/(site)/page.jsx`. `components/layout/` = chrome shared across the site (Header, Footer, MobileNav, the auth dialog). `components/ui/` = shadcn/ui primitives — treat these as generated/vendored; prefer adding more via `npx shadcn@latest add <component>` over hand-editing.
- **Auth dialog flow**: sign-in/sign-up is a single global dialog (`components/layout/auth-dialog.jsx`), not separate pages. Its open/closed state, mode (`signin`/`signup`), wizard step, and selected role live in `lib/store/auth-dialog.js` (Zustand, non-persisted). Any button that should open it calls `useAuthDialogStore`'s `openSignIn`/`openSignUp`, it doesn't route anywhere.
- **Auth/session state**: `lib/store/auth.js` is a persisted Zustand store (`user`, `token`) — this is the source of truth for whether someone is logged in, not cookies/session. `lib/axios.js` reads the token from this store in a request interceptor and attaches `Authorization: Bearer <token>`; its response interceptor normalizes every error to `new Error(message)` pulled from `error.response.data.message`, so `catch` blocks and mutation `onError` handlers can assume a plain `.message`.
- **Backend base URL**: `NEXT_PUBLIC_API_URL` in `.env` (currently `http://localhost:8000/api`, i.e. the Laravel app run locally) — all API calls go through the shared `api` axios instance in `lib/axios.js`, not ad-hoc `fetch`/`axios` calls.
- Path alias `@/*` maps to the app root (see `jsconfig.json`).
- shadcn config (`components.json`): style `base-nova`, JS not TSX, icon library `lucide`, Tailwind CSS variables enabled, no RTL.
- See the `fullstack-js-conventions` skill for the intended stack conventions (TanStack Query/Mutation for server state, TanStack Form + Zod for forms, Sonner for error surfacing, etc.) — apply these when adding data fetching or forms, since the current codebase predates most of that wiring.

## BackEnd (`BackEnd/my-laravel-app/`)

### Commands
Run from `BackEnd/my-laravel-app/`:
```bash
composer install
php artisan migrate         # SQLite by default (DB_CONNECTION=sqlite)
composer dev                # runs `php artisan dev` (serve + queue + logs + vite, per Laravel's default dev script)
composer test                # clears config cache, then `php artisan test`
php artisan test --filter=TestName   # run a single test
./vendor/bin/pint             # code style (Laravel Pint)
```

### Architecture
- Standard Laravel structure, still close to a fresh install: one `User` model, two API controllers (`app/Http/Controllers/Api/AuthController`, `UserController`), routes split across `routes/web.php` (just the default welcome view) and `routes/api.php`.
- **Auth is Sanctum token-based**, not session cookies: `POST /api/login` validates credentials and returns a plain-text token via `createToken()`; `GET /api/user` is protected by the `auth:sanctum` middleware and expects `Authorization: Bearer <token>` — this is the header the frontend's `lib/axios.js` interceptor sets.
- `POST /api/users` (registration) validates `role` against a fixed `client|artisan|admin` enum and an optional `profession` field — reflects the product's client-vs-provider account split described above.
- Migrations currently only cover `users`, `cache`, `jobs`, and Sanctum's `personal_access_tokens` — the domain model (requests/demandes, provider verification levels, missions, etc.) is not built yet.
